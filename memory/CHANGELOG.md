# Changelog

Newest first. Format: `YYYY-MM-DD · area · what changed · action needed (if any)`

- 2026-11-20 · api (AI track) · **AI review pipeline + REST API** in `apps/api`: Claude calls (`src/ai-review/`), 3 BullMQ jobs (`analyze-document`, `revise-document`, `summarize-for-recipients`) + `send-signing-invite`, routes for reviews / messages / edits / parties / versions / `GET /sign/:token/summary` / `GET /me/ai-usage`, documents upload, signature requests. New packages `@lex/contracts` (the frontend builds against `packages/contracts/src/ai.ts` + `mocks/`) and `@lex/crypto` (canonical hashing + certificate lines). Actions for everyone: `pnpm install`, `cp apps/api/.env.example apps/api/.env` and fill `ANTHROPIC_API_KEY`, **`pnpm services:up`** (Postgres + the new **Redis on 6379**), **`pnpm db:migrate`** (migration `0001_ai_tables`: documents, ai_reviews, ai_issues, ai_review_messages, ai_edits, signature_requests, recipients, recipient_summaries, ai_usage). Auth is not built yet, so the sender routes accept a dev `x-user-id` header outside production — replace `CurrentUserGuard` when login lands. Law search and document extraction call `apps/lex-api` when `LEX_API_KEY` is set, and use fixtures otherwise (`LAW_SEARCH_MODE`). Frontend team: `pnpm seed:demo` prints a seeded sender, review and signing link, and `GET /sign/:token/summary` is live — add it to the `apps/sign` relay allowlist.
- 2026-11-20 · lex-api · New app `apps/lex-api` (law search service for the AI review), port **5001**, run with `pnpm dev:lex`. Needs Postgres + pgvector (`docker compose up -d` in that folder) and its own `.env` from `.env.example`. Run `pnpm install` at the root. Not needed to run web/sign/api.
- 2026-11-20 · db · Auth schema (based on tms, no tenancy): `agencies`, `users` (agency_id null = individual, else one agency + agency_role), `sessions` (refresh rotation, like tms), `email_codes` (6-digit code via Resend for reset/set password). Replaced the test `users` table; migration regenerated as `0000_init`. Action: reset your local DB (`docker compose down -v && pnpm db:up && pnpm db:migrate`). Test endpoints now take `{ email, fullName }`.
- 2026-11-20 · api, db · Postgres in Docker (`pnpm db:up`, port **5434**) + Drizzle ORM in `apps/api`. First table `users` (id, email, name, created_at); test endpoints `GET/POST /users`. Action: `cp apps/api/.env.example apps/api/.env`, `pnpm install`, `pnpm db:up`, `pnpm db:migrate`.
- 2026-11-20 · docs · Added root `README.md` (LexHackathon: overview, apps & ports, getting started, rules).
- 2026-11-20 · docs · Rule: no need to test/build/lint after every change; check before commit/demo or when asked.
- 2026-11-20 · sign · New Next.js app `apps/sign` for public users who sign (no login), port **3001**. Page `/sign/[token]` is a placeholder for now. Run `pnpm install`, then `pnpm dev:sign`. Copy `apps/sign/.env.example` to `.env.local`.
- 2026-11-20 · web, api · Ports: frontend `apps/web` → **3000**, backend `apps/api` → **5000**. Update your `apps/web/.env.local` to `API_URL=http://localhost:5000`.
- 2026-11-20 · docs · Added `CLAUDE.md` with the hackathon rule (no RLS / tenant isolation, plain users & agencies tables, MVP first) and this `memory/` folder.
- 2026-11-20 · roadmap · Signing link can be opened many times but signed only once; it closes after signing. Receiver sync to existing accounts moved to "Later — only if time allows". RLS removed from the plan.
